# 在服务器上打包（jar 225MB，本地传太慢）

## 为什么要在服务器上打

fat jar 已经 225MB。从本地 `scp` 上传一次要 1~20 分钟（取决于网络），
中途断掉还得重来。服务器有 JDK 21 + Node 18 + Maven，**编译只要约 8 分钟**，
而且产物直接落在服务器上，不用再传。

## 首次准备（只做一次）

服务器缺三样东西，`scripts/sync-to-server.ps1` 只管同步源码，
工具链需要手工装一次：

```bash
# 1) Maven（服务器没有）
cd /opt/tools
curl -sSL -o maven.tar.gz \
  "https://repo.maven.apache.org/maven2/org/apache/maven/apache-maven/3.9.9/apache-maven-3.9.9-bin.tar.gz"
tar xzf maven.tar.gz && rm maven.tar.gz

# 2) JDK 21（服务器 /usr/lib/jvm 下只有 JRE 21，完整的 JDK 是 Java 8，编不了）
#    GitHub 在这台机器上不通，用清华镜像
cd /opt/tools
curl -sSL -o jdk.tar.gz \
  "https://mirrors.tuna.tsinghua.edu.cn/Adoptium/21/jdk/x64/linux/OpenJDK21U-jdk_x64_linux_hotspot_21.0.13_9.tar.gz"
tar xzf jdk.tar.gz && rm jdk.tar.gz
```

> ⚠️ **服务器上 `java` 指向的是 JRE**（`/usr/lib/jvm/jdk-21.0.6+7-jre/bin/java`），
> 直接用会报 `No compiler is provided in this environment. Perhaps you are running
> on a JRE rather than a JDK?`。`remote-build.sh` 会自动把 `JAVA_HOME` 指到
> `/opt/tools/jdk-21*`，所以**不要**在别处硬编码 `JAVA_HOME`。

## 日常用法

```powershell
# 增量：只传源码（约 5MB），然后在服务器上打包
.\gb28181-platform-starter\scripts\sync-to-server.ps1 -Build

# 首次或原生库有变动：带上 linux64 原生库（142MB）
.\gb28181-platform-starter\scripts\sync-to-server.ps1 -Full -Build

# 只同步不打包
.\gb28181-platform-starter\scripts\sync-to-server.ps1
```

打包产物在服务器 `/opt/gb28181-src/gb28181-platform-starter/target/`，
部署时拷到 `/opt/gb28181/` 再 `./gb.sh restart`。

## 传什么、不传什么

| 内容 | 是否同步 | 说明 |
|---|---|---|
| 各模块 `src/`、`pom.xml` | ✅ 每次 | 几 MB |
| `models/*.onnx` | ✅ 每次 | 3.5MB |
| `sdk-dahua/lib/linux64`、`sdk-hikvision/lib` | ⚠️ 仅 `-Full` | 195MB，基本不变 |
| `sdk-dahua/lib/win64` | ❌ 从不 | 服务器是 Linux，用不到 |
| `target/`、`node_modules/` | ❌ 从不 | 服务器重新生成 |
| `src/main/resources/static/` | ❌ 从不 | 服务器上 `npm run build` 生成 |
| `sdk/`（厂商原始包） | ❌ 从不 | 构建不需要 |
| `docs/`、`record/`、`download/` | ❌ 从不 | 与构建无关 |

## 两个必须注意的坑

### 1. `com.netsdk:netsdk` 不在 Maven 中央仓库

这个厂商私有包本地是手工 `install` 的，服务器首次构建会因为找不到它而失败。
`sync-to-server.ps1` 会自动把它推到服务器的 `~/.m2/repository/com/netsdk/`。

### 2. 不要把 tar 通过 PowerShell 管道喂给 ssh

```powershell
# ❌ 错：PowerShell 的管道按文本解码原生 stdout，二进制归档会被破坏，
#    对端 tar 报 exit 2
& tar -czf - <dirs> | & ssh ... "tar xzf - -C ..."

# ✅ 对：先落盘再 scp（脚本里就是这么做的）
& tar -czf $archive <dirs>
& scp -P $Port $archive "${Remote}:/tmp/x.tar.gz"
& ssh -p $Port $Remote "tar xzf /tmp/x.tar.gz -C $RemoteDir"
```

## 编码约定（PowerShell 5.1）

- **`.ps1` 脚本里不要写中文**：PS 5.1 按 ANSI(GBK) 读无 BOM 的 `.ps1`，
  中文会被解成乱码并导致「字符串缺少终止符」之类的解析错误。
  需要中文注释就写进 `.md` 或 `.sh`。
- **`.sh` 脚本必须 LF + 无 BOM**，否则 bash 报 `$'\r': command not found`。
- `ssh` 往 stderr 写进度信息，`$ErrorActionPreference='Stop'` 会把它当终止错误。
  脚本里对原生调用临时切到 `'Continue'` 并自己检查 `$LASTEXITCODE`。
